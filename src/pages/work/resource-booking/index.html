UX case study

Resource Booking System for Teachers

Making recurring room booking clearer, faster and more flexible.

A web-based room booking system that helps teachers book multiple rooms for recurring sessions based on specific preferences. The project was developed through low-, mid-, and high-fidelity prototypes and is currently paused after the first design iteration, ahead of a second user test.

Role
UX/UI
Tools

Methods
User testing · iteration

Status

01The problem

Teachers often face challenges when booking classrooms and equipment for their courses. Existing booking systems can be time-consuming and require users to navigate multiple pages before finding a suitable room. This project explores a more efficient and user-friendly booking experience.

Requirements — scenario breakdown
  • Allow booking of three rooms.
  • Ensure each room accommodates a minimum of 20 participants.
  • Ensure all selected rooms are located within 500 meters of each other.
  • Allow the same rooms to be used for multiple exercises.
02Mid-fidelity prototype — Figma

Built to work out the booking logic first: search by room type, equipment, building, date, time and seats — with multiple rooms, multiple dates, system-suggested rooms, and managing bookings. All components in the Figma prototype were created from scratch. The logic starts by asking the user what, where, when.

03Usability Test 1 · 5 users

I tested the mid-fidelity prototype with five users to understand how they used the room booking system and to identify where the experience became difficult or unclear.

Direct usability findings
01
The search bar required too many clicks.
Users sometimes needed to click twice to select an option and move to the next field.
02
Time selection needed improvement
Selecting a start/end time from the search bar wasn't smooth enough.
03
Users wanted recommendations before pressing Search
Users expected recommendations while making their selections, not only after pressing Search.
04
Selecting time from the schedule needed visual improvement
The old Room Schedule already showed rooms and their available/busy times, and selecting a booking time from it was functionally clear, but the visual presentation needed improvement.
Gaps I identified while evaluating the prototype
05
No quick way to find a room available now
The prototype had no dedicated path for "which room can I use right now?"
06
No complete way to browse all rooms
There was no catalogue experience for browsing rooms and comparing them.
07
Room Schedule was difficult to access
It wasn't clearly available as one of the system's main destinations.
04Design decisions

Each decision responds directly to a numbered finding or gap from Usability Test 1.

01
Selecting an option now completes the step and moves to the next field
02
Redesigned time-selection interaction
03
Recommended rooms for you, shown below the search bar as requirements are selected
04
Clearer start/end time selection directly from a room's availability timeline
05
Adding Available Now page to the navigation bar
06
Adding Our Rooms — the full catalogue to the navigation bar
07
Added as its own top-level destination in navigation bar
05High-fidelity prototype — Claude Design

Usability Test 1 surfaced both interaction problems and gaps in the booking experience. I used Claude Design to move quickly from those findings to this high-fidelity prototype — directing decisions, reviewing what it produced, and refining it. It includes the design responses above, but has not been tested yet.
